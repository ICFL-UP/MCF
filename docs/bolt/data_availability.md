# Data availability (Springer-format statement + dataset provenance)

## Statement (paste into the manuscript back matter verbatim)

> **Data availability.** The cross-chain transaction (CCTX) dataset analysed in this
> study is derived from the publicly available XChainWatcher dataset
> (arXiv:2410.02029), covering the Ronin (March 2022) and Nomad (August 2022) bridge
> incidents (83,079 transactions, of which 12 lacking an upstream USD valuation are
> dropped at build time; 58,146 train / 24,921 test under a leakage-free
> time-based split; positives: 380 Nomad rows, 2 Ronin rows). The derived splits are
> regenerated deterministically by `make data`
> (`scripts/fetch_cctx.py`) and verified against the SHA-256 checksums published in the
> repository (`data/cctx/*.parquet.sha256`) and reproduced below. Supplementary
> synthetic traffic is generated by `monitor/generator.py` with fixed seeds
> (log-normal values, Poisson arrivals, Zipf destinations). All code, configuration,
> logs, and figures are available on GitHub and archived at Zenodo
> (DOI: **[insert on deposit; see docs/bolt/reproducibility.md checklist]**); every
> reported number is reproducible with the single command `make all` (the invariant
> suite it chains additionally requires Foundry's `forge` on `PATH`, installed via
> `foundryup`; the log/figure evidence chain alone regenerates with `make reproduce`,
> which needs no Foundry).

## CCTX split checksums (SHA-256)

| File | SHA-256 |
|---|---|
| `data/cctx/train.parquet` | `2e509859f00235796ef890f30ede1e4b405937303ed02e1e274e33bd9e380f86` |
| `data/cctx/test.parquet` | `079e4c4d5b510e260d0f95128ad7883c7860141a764701617a6baf2fd47cd0d0` |

Regenerate & verify: `make data` then
`cd data/cctx && sha256sum -c train.parquet.sha256 test.parquet.sha256`.
`make data OFFLINE=1` produces a clearly-labelled synthetic stand-in whose checksums
will NOT match this table: the mismatch is the intended tamper/fallback signal.
